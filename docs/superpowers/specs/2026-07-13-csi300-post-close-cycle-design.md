# CSI 300 收盘后自动模拟交易设计

## 1. 目标

把现有由定时任务临场组合命令的 CSI 300 模拟交易流程，收敛为一个确定、幂等、
失败关闭的收盘后入口。入口只做 scored multi-factor baseline paper trading；DQN 保持
诊断状态，任何数据、成分、manifest 或执行异常都不得改变正式纸面账户。

本阶段不连接真实券商，不调整 70 分、0.8 置信度、单股 8% 上限或 8%/9%/10%
回撤规则。连续八周 paper evidence 通过前，盈利仍是待验证目标。

## 2. 已确认边界

- 信号日 D 收盘后生成目标，D+1 开盘执行，D+1 收盘估值。
- 每个研究输入由不可变 raw/processed manifest 和 SHA-256 标识。
- 当前官方 CSI 300 成分必须为 300 只，并与历史成员区间在 `as_of` 日一致。
- 上游调用必须有硬超时；超时、缺失、陈旧、恒定或未来泄漏均失败关闭。
- 个人分红税、最低佣金、印花税、滑点、T+1、停牌、涨跌停和公司行为继续生效。
- DQN 不传入目标生成或 paper execution。

## 3. 方案选择

保留现有自由文本编排无法保证每次执行完全一致。直接迁移到数据库、消息队列和独立
交易服务则超出当前日频研究系统所需规模。本设计采用单一确定性 CLI，复用现有 CSV、
JSONL、manifest 和执行引擎，并把运行状态显式保存在 paper pipeline state 中。

## 4. 架构

### 4.1 不可变增量父链

价格、点时因子和公司行为采集器新增 `--append-from`。新 raw run 只保存新请求区间，
`parent_manifest` 指向上一成功 raw run。构建器递归验证父链中的 manifest 和 artifact
哈希，检测循环与不兼容请求，并按“父级在先、子级覆盖同一业务键”合并后生成新的完整
processed snapshot。

信号价格父链只允许后复权（`hfq`）。后复权不会因未来公司行为重写既有历史尺度；前复权
（`qfq`）会随新除权事件改变过去价格，违反 immutable 父链假设，因此只能作为单次诊断
快照，不能 append。成交价格继续使用 `adjust=none`。

业务键如下：

- 价格：`(symbol, trade_date)`；
- 信息记录：`record_id`；
- 公司行为：标准化后的事件唯一键。

这既保留完整历史来源，又避免每天重复下载五年数据。链长在八周验证期内可接受；后续
可在不改变语义的前提下做周期性压实，但不属于本阶段。

### 4.2 当日决策报告

日常运行对完整数据集执行相同 data-health 门禁，但只输出 `as_of` 日的300只股票评分、
风险告警、输入哈希和配置，不重复生成完整回测、RL dataset 或数GB因子分析。完整正式
回测按代码、数据定义或周期性研究需要单独运行。

当日风险分两层：数据集产生市场/基本面静态告警；paper 账户在执行前一日目标并按收盘
估值后，用真实持仓成本与账户状态计算持仓风险。任一 `reduce` 或 `liquidate` 告警会阻止
对应新多头目标，组合回撤仍由共享状态机统一缩放。

### 4.3 原子 paper 提交

正式账户不直接传给子命令。收盘后入口先复制到账户暂存文件，在暂存区域依次完成：

1. 执行上一交易日排队目标；
2. 应用公司行为、税费和 A 股成交限制；
3. 按收盘价更新实际/影子 NAV 与回撤状态；
4. 生成并排队当日新目标；
5. 生成日报、dashboard 和 cycle manifest。

只有全部步骤成功且输出哈希复核通过，才使用同文件系统 `os.replace` 更新正式账户和正式
日报。失败时保留原账户，写出独立失败记录。pipeline state 也在最后原子更新。

### 4.4 幂等与并发

每个账户只允许一个文件锁持有者。若 `as_of` 已成功完成且 cycle manifest、账户后置哈希
与 pipeline state 一致，重复调用返回成功并声明 `already_completed`，不再次成交。若账户
日期已前进但证据不一致，则失败关闭，禁止自动猜测或修复。

## 5. 数据流

1. 校验交易日、当前成分和上次成功 pipeline state。
2. 从上次 `as_of + 1` 到本次 `as_of` 采集双价格、因子和公司行为增量。
3. 递归验证 raw 父链并构建完整 processed snapshots；刷新 CSI 300 benchmark。
4. 检查所有输入最新交易日恰好等于 `as_of`，执行完整 data-health。
5. 写出小型当日决策报告。
6. 在暂存账户运行 paper cycle 和 dashboard。
7. 写出 cycle manifest，原子提交账户、报告和 pipeline state。

## 6. 错误处理

- 成分接口、采集器和子命令均有可配置硬超时，默认成分60秒、数据源单阶段30分钟。
- 当前成分不为300只或与历史 active members 不一致时立即停止。
- raw 父链丢失、哈希变化、循环、日期倒退或价格调整口径不一致时立即停止。
- 任一采集 scope 失败时保留该 raw run 作为诊断证据，但不构建决策、不改账户。
- 研究数据最新日期不是 `as_of` 时禁止用旧报告把账户日期向前推进。
- dashboard 或证据写入失败与交易计算失败等价，正式账户保持不变。

## 7. 测试与验收

- 单元测试覆盖父链合并、子级覆盖、循环、哈希篡改和不兼容请求。
- CLI 夹具覆盖成分超时、非300只、陈旧数据、data-health 失败和子命令失败。
- paper 集成测试证明失败后正式账户字节不变、成功后只提交一次、重复调用不重复成交。
- 固定夹具端到端覆盖 D 收盘排队、D+1 开盘成交、收盘估值和新目标排队。
- 完成前运行全量 pytest、compileall、CLI help、diff 检查和一次固定夹具全链路。

## 8. 运行证据

每个成功 cycle manifest 至少记录：`as_of`、代码 SHA、成分哈希、全部输入 manifest 与
artifact 哈希、数据健康结果、账户前后哈希、目标/成交/阻塞单/公司行为数量、实际与影子
NAV、回撤状态、benchmark NAV、是否计入八周连续证据。只有新鲜数据、全部门禁通过且
账户提交成功的交易日才能计入证据。
