# Phase 4 Research Run Design

Date: 2026-06-22
Branch: `codex/phase4-research-run`

## Purpose

Phase 4 turns the Phase 1-3 building blocks into one reproducible daily A-share
research run. The system should be able to take local feature, information,
fundamental, and capital-flow files, produce daily 35/25/25/15 stock scores,
build risk inputs, run a practical multi-symbol baseline backtest, and write a
JSON run report that can later be compared with DQN.

This phase deliberately keeps the trading logic simple. The priority is a
trustworthy baseline loop, not a complex strategy or live brokerage integration.

## Current State

The project already has:

- A-share symbol and daily-bar normalization.
- AkShare as the default provider and a Tushare token-aware boundary.
- A JSONL information repository with text-vs-stock-data retention classes.
- Weighted `ScoreInput` / `StockScore` scoring:
  - fundamental 35
  - technical 25
  - capital flow 25
  - sentiment 15
- Four-layer risk rule evaluation.
- Dated drawdown calculation.
- A one-symbol scored baseline runner.
- A selected-universe daily feature refresh script.

The missing production research link is that these components are not yet
assembled into a single run artifact. The current RL classes are placeholders,
so expanding DQN before this baseline exists would train on weak state inputs
and provide no reliable benchmark.

## Design Principles

- Daily A-share research first.
- Local deterministic files first; network fetch remains in earlier refresh
  scripts.
- One command should produce a reproducible run report.
- Prefer transparent rule-based mappings over opaque models.
- Keep model training out of Phase 4.
- Use existing module boundaries instead of adding a broad platform layer.

## Inputs

### Required

`--features`

CSV generated by `scripts/refresh_research_data.py`. Required fields:

- `symbol`
- `trade_date`
- `open`
- `high`
- `low`
- `close`
- `volume`
- `amount`
- `return_1d`
- `ma20`, `ma60`, `ma250`
- `close_above_ma20`, `close_above_ma60`, `close_above_ma250`
- `rsi14`
- `macd_line`, `macd_signal`, `macd_hist`, `macd_positive`
- `volatility20`

`--universe`

CSV with at least `symbol`, optionally `name` and `sector`.

### Optional

`--information`

JSONL produced by `scripts/fetch_information.py`.

`--fundamentals`

CSV keyed by `symbol` and optionally `trade_date`. Supported fields:

- `pe`
- `pb`
- `roe`
- `growth`
- `goodwill_ratio`
- `pledge_ratio`
- `st_warning`

If `trade_date` is omitted, the row is treated as the latest known value for
that symbol throughout the run.

`--capital-flow`

CSV keyed by `symbol` and `trade_date`. Supported fields:

- `main_net_inflow`
- `main_outflow_days`
- `margin_financing_positive`

`--market-state`

CSV keyed by `trade_date`. Supported fields:

- `index_below_annual_ma`
- `broad_market_drop_gt_3pct_count`

Missing optional fields should reduce score confidence or remove a risk input,
not fabricate data.

## Outputs

The runner writes:

```text
outputs/research_runs/<run_id>/run_report.json
```

The report contains:

- `run_id`
- input file paths
- date range
- universe symbols
- scoring rows by date and symbol
- missing score fields by date and symbol
- risk warnings by date and symbol
- trades
- daily portfolio equity
- drawdown summary
- performance summary

The JSON must be stable enough to use as a future DQN benchmark artifact.

## New Modules

### `fintech_quant.research.dataset`

Responsibilities:

- Load feature CSV rows.
- Load optional fundamentals, capital-flow, market-state, and information
  records.
- Normalize symbols and dates.
- Keep rows sorted by `(trade_date, symbol)`.
- Reject duplicate feature rows for the same `(trade_date, symbol)`.

This module should not score, trade, or evaluate risk.

### `fintech_quant.research.scoring`

Responsibilities:

- Convert a merged daily row into `ScoreInput`.
- Map Phase 3 technical features into technical score fields:
  - `close_above_ma20`
  - `close_above_ma60`
  - `rsi14 -> rsi`
  - `macd_positive`
  - `volume_confirmed`
- Use optional fundamentals for PE/PB/ROE/growth.
- Use optional capital-flow rows for main inflow, outflow days, and margin
  financing direction.
- Use optional information records for sentiment fields.

Initial sentiment mapping:

- `negative_event_count`: number of same-symbol records up to that date whose
  `risk_tags` include `negative_announcement`, `st_warning`, `regulatory_risk`,
  `pledge_risk`, or `goodwill_risk`.
- `limit_up_streak`: default missing unless supplied by a future sentiment
  source.
- `dragon_tiger_positive`: default missing unless supplied by a future
  sentiment source.

No external NLP model is introduced in Phase 4.

### `fintech_quant.research.risk_builder`

Responsibilities:

- Build `RiskInput` for each date and symbol.
- Use previous equity peaks to calculate portfolio drawdown during the run.
- Use per-position cost basis and current close to calculate single-position
  drawdown.
- Map optional fundamentals:
  - `st_warning`
  - `goodwill_ratio`
  - `pledge_ratio`
- Map optional capital flow:
  - `main_outflow_days`
- Map optional market state:
  - `index_below_annual_ma`
  - `broad_market_drop_gt_3pct_count`
- Map information risk tags into stock-specific watch/reduce inputs where
  possible.

The builder should keep risk inputs explicit and inspectable. It should not
hide risk logic inside the strategy.

### `fintech_quant.backtesting.portfolio_research_runner`

Responsibilities:

- Run a daily multi-symbol baseline portfolio.
- Buy candidates with score above the existing `ScoredBaselineStrategy`
  threshold.
- Sell or skip buys when `evaluate_risk` returns `REDUCE` or `LIQUIDATE`.
- Enforce simple A-share constraints:
  - 100-share lot size
  - max position weight, default 8%
  - no same-day sell after buy for the same symbol
  - simple commission rate
  - simple slippage rate
- Keep all trading at close price for Phase 4.
- Produce trades, equity curve, dated risk warnings, and summary metrics.

This runner is still research accounting, not live execution.

### `scripts/run_research_baseline.py`

Responsibilities:

- Parse input paths and run parameters.
- Load data through `fintech_quant.research.dataset`.
- Build scores and risk inputs.
- Run the portfolio baseline runner.
- Write `run_report.json`.
- Print the report path and key summary metrics.

Default output:

```text
outputs/research_runs/<YYYYMMDD-HHMMSS>-baseline/run_report.json
```

Tests may pass `--run-id` for deterministic fixture output.

## Trading Rules

The Phase 4 baseline is intentionally conservative:

- It only buys symbols with sufficient score and no blocking risk action.
- It caps each position to `min(max_position_weight, available_cash)`.
- It rounds shares down to the nearest 100-share lot.
- It does not pyramid into an existing position.
- It liquidates positions when portfolio drawdown reaches 15%.
- It reduces or exits single names when stock-specific risk is `REDUCE`.
- It records `WATCH` warnings but does not trade solely because of them.

This keeps the baseline simple enough to debug and strong enough to compare
against later DQN experiments.

## Performance Summary

The report should include:

- initial cash
- ending equity
- total return
- max drawdown
- trade count
- risk warning count
- turnover
- win rate for closed trades

Sharpe and annualized return can be added after the equity curve is stable.

## Error Handling

- Missing required feature columns fail fast.
- Duplicate `(trade_date, symbol)` feature rows fail fast.
- Optional files may be omitted.
- Missing optional factor fields are reported through `StockScore.missing_fields`.
- Unknown symbols outside the universe are ignored with no report pollution.
- Invalid numeric fields fail with file and field context.

## Tests

Phase 4 implementation should add tests for:

1. Loading and joining feature, fundamental, capital-flow, market-state, and
   information fixtures.
2. Converting joined rows to `ScoreInput` and `StockScore`.
3. Negative information tags increasing `negative_event_count`.
4. Building `RiskInput` from drawdown, ST, goodwill, pledge, capital outflow,
   and market-state rows.
5. Multi-symbol baseline trading with 100-share lots and max position weight.
6. Risk-triggered exit on portfolio drawdown.
7. Stable `run_report.json` schema from the CLI.

All tests must run offline.

## Out of Scope

- Live brokerage integration.
- DQN model training.
- Web UI.
- MCP server or Hermes interface.
- Minute-level or high-frequency data.
- External NLP or sentiment models.
- Parameter optimization.
- Full point-in-time fundamental accounting beyond the simple optional
  `trade_date` rule described above.

## Acceptance Criteria

Phase 4 is complete when:

- `scripts/run_research_baseline.py` can run on offline fixtures.
- It writes a deterministic `run_report.json` for a fixed `--run-id`.
- The report includes scores, risk warnings, trades, equity, drawdown, and
  summary metrics.
- The portfolio runner enforces 100-share lots and max position weight.
- Risk exits can be triggered by the 15% portfolio drawdown rule.
- Full test suite passes.
- The implementation is merged to `main` and pushed to GitHub.
