# Architecture Notes

## Design Assumptions

- A 股优先，因为用户更熟悉市场语境。
- 第一版做日频研究、训练、回测和模拟交易，不接实盘。
- RL 是核心研究模块，但必须和规则/多因子基线在同一回测框架下比较。
- 数据源先使用免费层工具，接口保留可替换能力。
- 训练数据可以下载到本地，但原始数据、处理后数据和模型文件不进 Git。

## Core Flow

```text
data providers -> feature pipeline -> strategy decision -> risk gate -> backtest/paper account -> report
```

## Current Implemented Interfaces

- `fintech_quant.data.akshare_provider.AkShareProvider` loads AkShare daily A-share
  bars through a narrow `history(symbol, start, end)` interface and normalizes
  fields into English OHLCV keys.
- `fintech_quant.backtesting.metrics.calculate_equity_metrics` calculates total
  return, annualized return, Sharpe ratio, and max drawdown from an equity curve.
- `fintech_quant.reports.research_results.DashboardDataSource` reads configured
  research artifacts into one dashboard-ready model. Its `DashboardConfig`
  includes market, frequency, execution mode, and source paths so future minute
  data, paper-trading output, or model-versioned result bundles can use the same
  dashboard UI contract.
- `fintech_quant.reports.dashboard` is a local Streamlit app for strategy
  comparison, PnL/equity review, data quality, and factor diagnostics.

## Dashboard Data Contract

The dashboard intentionally consumes stable local artifacts instead of ad hoc
notebook state:

```text
outputs/strategy_comparison_report.json  strategy/window metrics
outputs/baseline_backtest.json           baseline metrics and equity_curve
outputs/data_quality_report.json         source freshness and quality checks
outputs/factor_diagnostics_report.json   factor IC/rank IC diagnostics
data/processed/akshare_research_features.csv feature coverage summary
```

Future backtests should export one result bundle per strategy/run with:

```text
metadata -> metrics -> equity_curve -> trades -> diagnostics
```

This is required before the dashboard can show multi-strategy PnL lines rather
than only the current baseline equity curve.

## Dashboard Interaction Model

The dashboard default flow is designed for research decisions:

1. Pick validation mode and out-of-sample window.
2. Read the strategy recommendation and risk status.
3. Compare total return, Sharpe ratio, max drawdown, and trade count.
4. Inspect PnL/drawdown and single-strategy walk-forward behavior.
5. Check factor diagnostics and data operations before trusting a result.

The UI includes an explicit reload action because outputs are local files that
may be regenerated by later strategy or feature pipelines.

## RL Role

第一版采用单票 buy/sell/hold 决策接口：

- state: 单只股票的行情、技术指标、基本面和市场状态。
- action: buy, sell, hold。
- reward: 后续设计，至少要扣除手续费、滑点、错误持仓和回撤惩罚。
- constraints: T+1、涨跌停、停牌和仓位上限由回测/风控层执行，不让策略绕过。

## Data Storage

```text
data/raw/        原始下载数据，不进 Git
data/processed/ 处理后特征和训练样本，不进 Git
data/models/    训练后的模型和检查点，不进 Git
```

模型训练通常需要本地数据集和本地模型文件。小模型可以保存在 `data/models/`，后续如果模型变大，再引入 DVC、Git LFS 或对象存储。
